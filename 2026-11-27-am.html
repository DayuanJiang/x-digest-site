Opus 5.6传称提速一倍，Anthropic仍未发布后续

6 条帖子，合计浏览 35.8 万次

之前的报道：11月26日午间“Karpathy用Opus 5.5写出美国版“文明”地图”

一个 X 账号贴出所谓 Claude Opus 5.6 的泄露参数，称速度是 Opus 5.5 的两倍，帖子获得1800多个赞。Anthropic（开发 Claude 的 AI 公司）没有宣布这款模型，几家科技网站都写明传闻未经证实。时间线上还有用户整理了 Claude Code 云端会话的环境配置，也有人晒出用 Anthropic 的模型 Fable 5.2 做的游戏。

传闻内容
泄露帖称 Opus 5.6 每秒最多输出291个 token（模型处理文字的单位），首个 token 1到1.5秒就出来，token 用量省约三成。传言的 API 价格是每百万输入 token 4美元、输出20美元，快速模式再贵一倍。 X 用户
官方现状
Anthropic 的模型页面上没有 Opus 5.6，现有的 Opus 5.5 定价就是每百万 token 输入4美元、输出20美元，和这次传言的价格相同。别的传言说会降价两成或降到2美元和10美元，各种说法互相对不上。 Anthropic 官网、科技媒体
云端环境
一位用户整理说，Claude Code 的云端会话每次新开一台 Ubuntu 虚拟机（4核、30GB 硬盘），仓库已克隆好，预装 Docker 和 docker compose、测试用 Chrome、Node 20到22 和 git、gh 等工具。PostgreSQL 16 和 Redis 7 也装好了，但要自己用 service 命令启动。 X 用户
设置脚本
每个环境可以配一段在 Claude 启动前运行的设置脚本，约5分钟内跑完，文件系统就会缓存给之后的会话用。缓存只存文件不存运行中的进程，官方文档建议把 docker compose pull 写进脚本，镜像就不用每次重新下载。 Claude Code 文档

GPT-6.2 Astra 22分钟认出古速写本作者后续

5 条帖子，合计浏览 105 万次

之前的报道：11月26日午间“OpenAI修正计费，GPT-6.2 Astra额度消耗快四成”

科技网站 GIGAZINE 报道，加拿大劳里埃大学的历史学教授 Mark Humphries 把一本作者不明的1808年旅行速写本交给 OpenAI 的 GPT-6.2 Astra，它22分钟就给出作者人选，后来查证属实，转发报道的日文帖获得600多个赞。同一时期，斯坦福大学物理学家、也在 OpenAI 推理团队工作的 Venkatesa Chandrasekaran 发表了借助 GPT-6 Astra 完成的量子引力论文。时间线上对 OpenAI 模型的讨论，从计费出错转到了它做出的研究成果。

什么谜题
这本速写本藏在耶鲁大学的拜内克古籍善本图书馆，画的是1808年在加拿大蒙特利尔和威廉堡之间往返的旅程，2020年才从旧书店买回。当年这条路线每年有几百条船走，作者候选可能有几千人，Humphries 找了多年都没有线索。 GIGAZINE
怎么找到
Astra 拿到速写本图片和一些背景资料后，查遍历史学者常用的档案网站，从一位毛皮商人的日记里找到线索，推断作者是流亡英国后当上英军军官的法国小贵族 Rohan-Chabot 子爵。Humphries 调来子爵的旅行日记，笔迹和1808年6月画圣约瑟夫堡的记录都对得上。 GIGAZINE
量子引力
Chandrasekaran 11月25日在论文预印本网站 arXiv 发表83页论文，提出四维时空里引力的量子化方法，论文还没有经过同行评审。他说部分计算和证明是和 GPT-6 Astra 来回合作几个月得出的，共用约4亿 token，算力由 OpenAI 提供。 MLQ.ai、The AI Insider
学者看法
Humphries 预计到2027年春夏，历史学者会因为 AI 智能体做到人做不到的事而失去信心。他也认为历史学要不断重新解读过去，受 AI 的冲击不会像数学那么大。 GIGAZINE

shadcn团队做UI SDK，让智能体直接操作界面组件

5 条帖子，合计浏览 5.9 万次

界面组件库 shadcn/ui 的作者 shadcn 发视频介绍团队正在做的 UI SDK，中文 AI 博主宝玉给视频配上中文配音后转发。时间线上的其他开发者也在分享和 AI 智能体一起干活的做法和工具，从全程用语音写代码、批评 MCP 的设计，到让 AI 机器人账号帮忙分析 CI。以下用法和看法都来自个人账号。

界面工具
UI SDK 把界面组件拆成智能体能用的行为单元，例如打开弹出层、用方向键移动焦点。这样它和具体组件无关，同一套用法可以用在 React、Vue、Svelte、Solid 等框架上，文档在 ui-sdk.dev。 X 用户
批评协议
一位中文开发者认为，MCP（让 AI 连接外部工具的协议）和 Skills 能做的事，用 HTTP 服务加 OpenAPI 就能表达，而且很多 MCP 客户端要一直保持连接，多个智能体会吃掉大量内存。他还嫌把 Skills 放在 GitHub 上要克隆整个仓库，推荐 Cloudflare 在 GitHub 公开的技能发现提案 agent-skills-discovery-rfc。 X 用户
语音开发
一位日本开发者觉得用 AI 时打字是最大瓶颈，自己做了一个能语音输入输出的命令行工具，现在全程用语音开发，连这个工具本身也是用语音做出来的。 X 用户
反向利用
一位中文开发者回复一个 AI 机器人账号，让它下载开源项目 Apache OpenDAL 的源码，分析最近100次夜间构建（Nightly CI）出了哪些问题并提修复建议，还号召大家都这样让机器人账号干点活。 X 用户
标签交互
智能体客户端 Comma Agents 在做一种新的标签页交互，解决原生标签页放不下的问题，完成后会在 GitHub 的 afk-surf/comma 开源。 X 用户

税理士：年后一次补记账，不只影响75万扣除后续

4 条帖子，合计浏览 1.1 万次

之前的报道：11月26日晚间“国税厅：年后一次补记账拿不到75万青色扣除”

几位税理士（税务师）在时间线上分享税务提醒：有税理士指出，国税厅问答里不认可年后一次补记账的规定，针对的不只是新设的75万日元青色申告扣除。另有税理士提醒，父母按继承税评估价把土地卖给子女也可能被课赠与税，还有人列出两项防避税的公司税修改。以下是专业人士账号的解读。

补记账
一位税理士说，国税厅11月追加的问答写明，不认可年后一次补记账的规定不只针对75万扣除。发帖者认为记账要从一年一次改成日常工作。 国税厅、X 用户
亲属买卖
另一位税理士提醒，按继承税评估价卖给亲属就不会被课赠与税的想法很危险。过去的判例里有被认可的例子，但达到时价八成也不保证没问题，关键是弄清时价、价格要合理，而时价本身就很难算。 X 用户
公司税制
一位税理士兼会计师指出，新公布的修改里有两项是为防避税：完全控股集团内部交易的“捐赠调整”规则要修改，公司分立等情况下和高价特定资产有关的消费税免缴特例也要修改。 X 用户
个体户
一位做法人化咨询的账号提醒，个体户收入增加时，累进税率、国民健康保险费和住民税会一起涨，建议核对确定申告书、应税所得、国保、住民税和今后的利润预测。 X 用户

65岁以上护理保险费将分22档，所得120万起加收

3 条帖子，合计浏览 23.9 万次

厚生劳动省（主管医疗和社保的部门）26日向审议会提出方案，2027年度起提高合计所得120万日元以上的65岁以上老人的护理保险费，把收费档位从13档细分到22档。护理保险费是65岁以上的人按所得分档缴纳的保费，档位越高交得越多。日经的报道帖被多次转发，有人质疑为什么不按实际使用多少来定保费。

谁要多交
对象是扣除公共养老金等之后，合计所得在120万日元以上的65岁以上老人。低收入层的负担会减轻。 共同社、日经
怎么分档
现行13档里，从第7档（120万到210万日元）到第13档（720万日元以上）的7个档位各拆成两档，变成14档，其中8个档位的倍率上调。 读卖新闻
现在多少
保费由各市区町村定基准额，现在全国平均每月约6200日元，个人按所得交基准额的约0.46倍到2.4倍。 读卖新闻
下一步
涨幅和所得线还要再定，厚劳省打算年内敲定细节，2027年度起实施。 共同社、读卖新闻
